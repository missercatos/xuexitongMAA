关于git的使用:

首先你必须要创建自己的分支，git branch -b you_branch
正常的修改和上传步骤
然后再你的分支里git push origin you_branch
上传到你的远程分支上
你需要提交pr
gh pr create --title "you_title" --body "action_body" --base master --head you_branch
这里的话我会看见你的pr
我会gh pr list 查看你的pr
然后拉取你的pr: gh pr checkout you_PR_ID
在我的本地进行测试
没问题后我会
gh pr merge 2 --squash
进行合并
然后我会切换到本地分支 git checkout master
推送到干净分支git push clean master 

假如你还不是我们的内部开发者，你需要优先进行frok
gh repo fork missercatos/xuexitongMAA
接着你需要 git clone you/xuexitongMAA.git
将你复制的地址克隆到本地
你还需要为项目添加上游仓库
git remote add upstream missercatos/xuexitongMAA
你可以git remote -v来检查，你会看不同分支对应的不同项目地址。
再你修改完代码之后，你需要推送到你自己的远程分支，git push origin main
然后提交pr
我们推荐你先创建自己的分支，因为这个时候主分支已经连接了原仓库作为上游，直接在你的本地主分支修改后期合并会造成严重的冲突。
当你需要最新代码的时候你需要
git checkout master 到你的主分支
然后
git pull upstream main 拉取上游改动
git push origin master 把你拉取的更新改动到你的fork仓库
当你需要在你的开发分支进行更新的时候
再git checkout you-branch切换到你的开发分支
git merge master合并主分支到你的开发分支

当你位于我们项目里面的时候，不需要frok,当你需要最新代码的时候，你需要
git checkout master切换回主分支
然后git pull origin main拉取最新更新
接着git checkout you-branch切换回你的开发分支，git merge master合并到你的开发分支

假如说你在你的本地主分支修改，然后拉取最新更新到你的本地主分支，导致你的主项目受到了污染。
看看git log --oneline里的提交记录，找到你的哈希值，git format-path -1 哈希值删除掉
然后git reset --hard upstream/master将你的本地主分支变得和上游完全一样。
然后你在创建自己的分支，下次在你自己的分支里修改。

你在提交的时候要提交到你自己创建的新的远程分支，git push -u origin you_branch
我会看到，我可能会git push clean --delete you_branch删除掉不合规的修改
假如的修改合适。我会git fetch you_branch 将你的分支拉到本地进行测试。

关于开发环境：
本项目基于MAA框架进行开发，需要python3.11的开发环境，你需要创建虚拟
python vent ~/maa-venv
在bash下进入~/maa-venv/bin/activate
pip install MaaFw下载开发环境
export MAAFW_BINARY_PATH=~/maa-bin
设置环境变量

同时你还需要将C++的开发文件准备到~/maa-bin里
curl -L -o /tmp/MAA-linux.zip \
  "https://github.com/MaaXYZ/MaaFramework/releases/download/v5.12.3/MAA-linux-x86_64-v5.12.3.zip"

# 2. 解压
unzip /tmp/MAA-linux.zip -d /tmp/MAA-linux

# 3. 复制到目标目录
cp -r /tmp/MAA-linux/bin ~/maa-bin

# 4. 设置环境变量 (每次运行前)
export MAAFW_BINARY_PATH=~/maa-bin
